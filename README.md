# smart_home

# Building
prebuild
`cmake -B build -S . -DCMAKE_EXPORT_COMPILE_COMMANDS=TRUE`
build
`cmake --build build`

# Test
`ctest --build-dir build --output-on-failure`

# Документация

API-документация на русском языке генерируется Doxygen со стандартной встроенной темой.
Необходимы CMake и Doxygen; Graphviz используется для диаграмм, если установлен.

```sh
cmake -B build -S . -DBUILD_DOCS=ON
cmake --build build --target docs
```

Откройте `build/docs/html/index.html` в браузере. Доступны поиск и иерархия классов.
Чтобы отключить настройку документации, используйте `-DBUILD_DOCS=OFF`.

## Диагностическое логирование

Для сборки требуется пакет разработки spdlog (`find_package(spdlog CONFIG)`).
Если пакет не установлен, включите загрузку закрепленной версии v1.17.0:
`cmake -B build -S . -DSMART_HOME_FETCH_SPDLOG=ON` (требуется доступ к GitHub и Git).

Логирование синхронное и потокобезопасное. Диагностика выводится в stderr и
`logs/smart_home.log`, относительно текущего рабочего каталога. Измерения остаются
в stdout. Порог по умолчанию — INFO; файл ротируется при 5 МиБ, сохраняются три
архивных файла плюс текущий. Отдельная запись больше порога может превысить его.

```sh
./build/bin/smart_home --log-level=debug --log-file=logs/smart_home.log
./build/bin/smart_home --log-level=off --log-file=
```

| CLI | Переменная окружения | Значение по умолчанию |
| --- | --- | --- |
| `--log-level` | `SMART_HOME_LOG_LEVEL` | `info` |
| `--log-file` | `SMART_HOME_LOG_FILE` | `logs/smart_home.log` |
| `--log-max-size-mib` | `SMART_HOME_LOG_MAX_SIZE_MIB` | `5` |
| `--log-max-files` | `SMART_HOME_LOG_MAX_FILES` | `3` |

Приоритет для каждого поля: CLI > окружение > значения по умолчанию. Поддерживаются
формы `--ключ=значение` и `--ключ значение`; при повторении действует последнее
значение. Пустой путь отключает файловый вывод. Размер должен быть положительным,
число архивов — от 1 до 200000. Неизвестные аргументы и некорректные значения CLI
дают код выхода 2 до выполнения команд. Некорректное окружение вызывает
предупреждение и заменяется значением по умолчанию.

Уровни, без учета регистра: TRACE (трассировка), DEBUG (отладка), INFO (жизненный
цикл), WARN (обработанное отклонение), ERROR (ошибка операции с продолжением),
CRITICAL (фатальное завершение), OFF (отключение обычных записей). DEBUG и TRACE
доступны и в Release. Ошибка записывается один раз в месте обработки; физические
адреса и произвольный текст исключений в диагностику не копируются.

При невозможности открыть файл сохраняется вывод в stderr. Ошибки приемников
вызывают прямое предупреждение в stderr, не чаще одного раза за пять секунд,
и не меняют исключения бизнес-логики. Служебные сообщения об ошибках самого
логирования могут выводиться при OFF. До инициализации и после завершения WARN
и выше выводятся минимальным обработчиком в stderr. Инициализацией и завершением
владеет `main`; библиотеки не меняют глобальный реестр spdlog.
