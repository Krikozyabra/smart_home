# План реализации модуля device_management (Capability-Based подход)

Статус: согласован со спецификацией [spec.md](spec.md) и [design.md](design.md); реализован; результаты проверок приведены ниже.
Основание: `specs/device_management/spec.md`, `specs/device_management/design.md`, `AGENTS.md`.

## 1. Соответствие требованиям спецификации

| Требование | Описание | Реализация | Способ проверки |
|---|---|---|---|
| **DM-001** | Конструктор принимает storage, фабрики, registry и ontology | Сигнатура конструктора `DeviceManager` без маппинга типов | Тесты создания экземпляра, передача мока/реальной онтологии |
| **DM-002** | Регистрация обнаруженного устройства, идемпотентность, сохранение значений | Метод `registerDiscoveredDevice`, валидация фабрики, `getOrCreate`, синхронизация графа | Тесты на первую и повторную регистрацию, проверка сохранности состояния драйвера |
| **DM-003** | Восстановление сохранённых устройств, двухфазная подготовка, подсчёт добавленных | Метод `restoreStoredDevices`, предварительное создание драйверов во временном векторе | Тесты восстановления 0, N устройств, отмена при сбое фабрики, повторное восстановление |
| **DM-004** | Синхронизация узлов устройств в онтологии (`local_id`, `name`) | Создание узла через `ontology.addDevice`, валидация существующего узла по имени | Проверка узлов в LadybugDB, проверка ошибки при несовпадении имени |
| **DM-005** | Синхронизация связей `HAS_FEATURE`, проверка каталога возможностей | Чтение возможностей из дескриптора драйвера, проверка каталога, `addDeviceAbility` | Проверка связей в онтологии, тест на выброс ошибки при отсутствии возможности в каталоге |
| **DM-006** | Дополнение отсутствующих элементов, сохранение комнат, строгая валидация | Дополнение графа для активных устройств, отсутствие изменений комнат, отказ при лишних связях | Тесты сохранения комнат, тесты на отказ при лишних связях возможностей |
| **Ошибки** | `UnsupportedDriverError`, `runtime_error`, `logic_error` | Соответствующая иерархия исключений при различных отказах | Негативные тесты с `expectException` для всех краевых случаев |
| **Логирование** | Info для восстановления, Debug для регистрации | Вызовы `logging::log` с контекстом `DeviceId` | Проверка отсутствия падений и наличия контекста в логах |

## 4. Результаты верификации

Проверено на рабочей машине:

- `cmake --build build -j 2` — успешно, включая основной runtime.
- `ctest --test-dir build --output-on-failure` — 29/29 наборов пройдены,
  включая device_manager, discovery, logging и четыре набора runtime.
- `cmake --build build --target docs` — успешно, без предупреждений Doxygen.
- `git diff --check` — без ошибок.

Тесты менеджера дополнительно проверяют произвольную возможность из дескриптора,
частичный отказ регистрации в registry, повторную попытку и сохранение уже
активных драйверов при ошибке подготовки остальных.
Проверки аппаратуры Raspberry Pi не выполнялись.
