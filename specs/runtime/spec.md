# Основной цикл программы

ID: Runtime

Статус: runtime реализован; автоматические проверки выполнены на рабочей машине.
Проверки Raspberry Pi и ThreadSanitizer остаются невыполненными (см. plan.md).
Технические решения: [design.md](design.md). План: [plan.md](plan.md).

## Цель

Создать основной цикл приложения, объединяющий обнаружение устройств,
управление ими через консоль, онтологию и сохранение полного состояния.
Целевая платформа — Linux на Raspberry Pi 4b 8/120 (SD-card).

## Требования

- RT-001: Основной цикл работает до запроса завершения и продолжает обслуживать
  события при ожидании консольного ввода и выполнении фоновой работы.
  Длительные вычисления, включая будущую обработку аудио или текста ИИ,
  выполняются вне основного потока и возвращают результаты событиями.
  Постоянная загрузка ядра на 100%, привязка к CPU и численная гарантия
  задержки не требуются. Файловое сохранение выполняет отдельный worker.
- RT-002: Основной цикл, композиция компонентов и вспомогательная логика runtime
  находятся в `src/main.cpp`. Отдельная библиотека runtime не создаётся.
- RT-003: До цикла система создаёт хранилище онтологии, базовые комнаты
  и возможности, восстанавливает сохранённые устройства и связи.
  На первом запуске устройства добавляются в граф при обнаружении внутри цикла.
  Узлы устройств и связи возможностей дополняет `DeviceManager`; runtime
  готовит каталог возможностей и комнаты, назначает комнаты новым устройствам.
  Пользовательские команды изменения онтологии пока отсутствуют.
- RT-004: До цикла настраиваются создатели протоколов (включая `"simulated"`)
  и `DeviceRegistry`.
- RT-005: До цикла создаются `DeviceManager`, `CommandDispatcher`,
  `DiscoveryService` и остальные необходимые службы.
  Зависимости передаются явно, без глобального поиска сервисов.
- RT-006: На первой итерации система имитирует обнаружение двух ламп и датчика
  температуры. Повторное обнаружение по `scan` не создаёт дубликатов,
  сохраняет прежние `DeviceId` и текущие значения. Консоль поддерживает
  адресные и групповые команды чтения и изменения возможностей.
  Ошибки ввода и выполнения выводятся пользователю и не завершают цикл.
- RT-007: После каждой логической операции, изменившей состояние, система
  запрашивает сохранение согласованного полного снимка в постоянную память.
  Снимок включает инвентарь, идентификаторы и привязки драйверов, значения
  возможностей и граф онтологии. Сохранение также доступно по `save`
  и выполняется при штатном завершении. Периодического сохранения нет.
  При ошибке изменения остаются в RAM с явным сообщением пользователю.
  Повторная попытка выполняется по `save`, следующему изменению
  или при завершении.
- RT-008: При запуске восстанавливается зафиксированное согласованное поколение
  состояния с прежними `DeviceId` и значениями возможностей. Рабочие базы,
  значения и промежуточные снимки находятся в RAM. После аварии допускается
  потеря ещё не зафиксированных изменений; данные разных поколений
  не смешиваются. Повреждённое зафиксированное состояние вызывает ошибку
  запуска без молчаливого сброса к значениям по умолчанию.

## Консоль

```text
help
list
show <id>
scan
save
exit

<id> <operation> [arguments]
<room> <type> <operation> [arguments]
```

`id` — локальный DeviceId, `room` — ID комнаты из онтологии,
`type` — `light` или `temperature_sensor`. Операции соответствуют
дескрипторам устройств и существующему CommandDispatcher. Категории `type`
являются соглашением консоли runtime, определяются по составу возможностей устройства
(`on_off` / `brightness` для `light`, `temperature` для `temperature_sensor`)
и не являются полем устройства в онтологии.

```text
1 brightness.set 75
1 on_off.set true
living_room light color.set 10 20 30
bathroom temperature_sensor temperature.get
```

Групповая команда выполняется для всех совпавших устройств с отдельным
результатом для каждого. Ошибка одной цели не отменяет уже выполненные
действия и не мешает остальным. Отсутствие совпадений — ошибка команды.
Пользовательское редактирование онтологии не поддерживается.

Для сохранения одна логическая операция — одно обнаружение или одна команда,
включая групповую. При частичном успехе сохраняется фактически полученное
состояние. Чтение и операции без изменения состояния нового снимка не требуют.

## Завершение и ошибки

- `exit`, EOF, SIGINT и SIGTERM запускают штатное завершение: прекращение
  новых команд, финальное сохранение, ожидание worker и освобождение ресурсов.
- Обработчики сигналов не выполняют сохранение, logging и другую сложную работу.
- Ошибка финального сохранения даёт ненулевой код выхода. Доступные рабочие
  файлы сохраняются для восстановления.
- Невозможность проверить конфигурацию, загрузить состояние или создать
  необходимые ресурсы завершает запуск с диагностикой.
- Очередь снимков ограничена. При заполнении новые изменяющие команды
  отклоняются до выполнения; чтение, обработка событий и завершение доступны.
- Результат изменения устройства и результат сохранения сообщаются раздельно.
  Сохранение подтверждается после завершения протокола фиксации.

## Границы

- Текущий этап объединяет devices, descriptors, drivers, registry, command,
  execution, storage, device_management, discovery, ontology и logging.
- MQTT, audio, OWW и обработка текста пока не подключаются. Требование
  к будущим длительным задачам не означает реализацию ИИ на этом этапе.
- Основная реализация находится в `src/main.cpp`. Допустимы необходимые
  изменения `src/CMakeLists.txt`, тестов, `tests/CMakeLists.txt`,
  `cmake/Docs.cmake` и спецификаций. Новые модули согласуются отдельно.
- Сохраняются границы фабрик, реестров, DeviceManager, dispatcher и хранилищ.
  Требования внешнего SDK не распространяются автоматически на C++17 приложения.
- Прямой рабочей базы на SD-карте и автоматического disk fallback нет.
- Общей транзакции SQLite и LadybugDB нет. Согласованность постоянного
  состояния обеспечивает runtime посредством публикации целого поколения.

## Критерии приёмки

- Все службы и реестры созданы до цикла; устройства проходят через существующие
  механизмы обнаружения, управления и создания драйверов.
- Две лампы и датчик обнаруживаются на первой итерации. Повторный scan
  сохраняет идентичность устройств и значения возможностей.
- Адресные и групповые команды работают. Ошибки команды или отдельной цели
  не завершают приложение и не скрывают результаты остальных целей.
- Неполная строка ввода и незавершённая фоновая задача не останавливают
  обработку других событий. Обязательного busy loop нет.
- После каждой изменившей состояние операции запрашивается сохранение;
  чтение и отсутствие изменений лишнего снимка не создают.
- Инвентарь, граф и значения восстанавливаются из одного поколения.
  Прерывание записи не приводит к смешению файлов разных поколений.
- После ошибки сохранения изменения остаются в RAM с явным статусом.
  Повторное сохранение может завершиться успешно.
- exit, EOF, SIGINT/SIGTERM завершают работу с финальным сохранением;
  повторный запуск восстанавливает зафиксированное состояние.
- Второй процесс с тем же постоянным каталогом отклоняется.
- Рабочие данные находятся в RAM. Если RAM недоступна, запуск завершается
  с ошибкой. Проверки на Raspberry Pi выполняются отдельно.

## Конфигурация реализации

| CLI / переменная окружения | По умолчанию |
|---|---|
| `--runtime-state-dir` / `SMART_HOME_RUNTIME_STATE_DIR` | `data/runtime` |
| `--runtime-ram-dir` / `SMART_HOME_RUNTIME_RAM_DIR` | `/dev/shm` |
| `--runtime-snapshot-capacity` / `SMART_HOME_RUNTIME_SNAPSHOT_CAPACITY` | `4` |

CLI поддерживает `--имя=значение` и `--имя значение`, последнее повторение
побеждает окружение. Пути непустые, ёмкость — положительное целое число;
проверка файловой системы выполняется при открытии ресурсов.
RAM-каталог должен находиться на tmpfs/ramfs. Параметры и переменные
`--ontology-*` / `SMART_HOME_ONTOLOGY_*` самостоятельной библиотеки
отклоняются, включая попытки включить периодическое сохранение или fallback.
Старый демонстрационный файл ontology автоматически не импортируется.

Формат поколения v1: `state.sqlite`, `ontology.lbdb`, `metadata`.
Метаданные содержат номер формата, ревизию и SHA-256 обоих файлов;
версия/ревизия также проверяются в SQLite. Дополнительно проверяются
типы, диапазоны значений, состав инвентаря и соответствие устройств,
комнат и возможностей графа. CURRENT допускает только имя поколения
внутри `generations`, без произвольного пути и символических ссылок
на файлы поколения. Незавершённые поколения не выбираются по номеру.

Ввод ограничен 65536 байт на строку: слишком длинная строка отклоняется,
последующие строки продолжают обрабатываться. EOF обрабатывает последнюю
непустую строку без завершающего перевода строки.
