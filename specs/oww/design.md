# Технические решения

- Используется OpenWakeWord
- Оптимизировано под ограниченные ресурсы платы

## Пайплайн и модели

Используется ONNX Runtime с CPU Execution Provider. Зависимость закрыта PIMPL:
публичные заголовки и потребители остаются C++17. Модуль — статическая библиотека
`SmartHome::Oww`; `SmartHome::Logging` и ONNX Runtime подключены приватно.

Одна модель ключевого слова не принимает PCM напрямую. Реализованы три этапа,
соответствующие [потоковому препроцессору OpenWakeWord v0.6.0](https://github.com/dscripka/openWakeWord/blob/v0.6.0/openwakeword/utils.py):

1. К очередным 1280 отсчётам добавляются последние 480 отсчётов прошлого кадра.
   Float32-тензор `[1, 1760]` сохраняет исходную амплитуду signed PCM16.
   Модель спектрограммы возвращает восемь строк по 32 mel-признака.
2. Применяется преобразование `mel / 10 + 2`. Последние 76 строк передаются
   модели акустических признаков как `[1, 76, 32, 1]`; результат содержит 96 чисел.
3. Последние `N` векторов подаются классификатору как `[1, N, 96]`. `N` читается
   из модели при создании, допустимы значения 1..120 — размер истории upstream.
   Единственный выход — готовая вероятность; дополнительный sigmoid не применяется.

Имена входов/выходов читаются из ONNX, а не зашиваются в коде. Все модели должны
иметь по одному входному и выходному float32-тензору. Размерности входов и
выходов проверяются при создании; единичные оси выхода допускаются как в upstream.
Успешная проверка существования
файла сама по себе не гарантирует пригодность его содержимого.

## Состояние и ресурсы

Модели и имена тензоров загружаются один раз. Входные векторы и выходные тензоры
создаются до обработки пользовательского аудио; далее используются те же буферы.
Прогрев выполняется тишиной на протяжении `ceil(76 / 8) + N` кадров, заполняя
весь контекст реальными признаками тишины. Это намеренное воспроизводимое
начальное состояние вместо случайной истории Python-реализации OpenWakeWord;
побитовое совпадение первых предсказаний с ней не обещается. С первого кадра
используется полный вход спектрограммы с 480 отсчётами предыстории.

Сессии исполняются последовательно, `inter_op_num_threads = 1`, число потоков
внутри операции задаётся `inference_threads` (по умолчанию 1). Активное ожидание
потоков отключено. В горячем цикле модуль не увеличивает контейнеры, не создаёт
тензоры, не читает файлы и не логирует кадры. ONNX Runtime может выполнять
собственные внутренние выделения памяти; реальные лимиты CPU/RAM измеряются
на целевой плате и выбранных обученных моделях.

Экземпляр используется одним аудиопотоком последовательно. Между независимыми
экземплярами нет общего аудиосостояния. Функция не проверяет длину входного
буфера: полный кадр — предусловие. Это отражено в документации указателя,
типе `PcmFrame = std::array<int16_t, 1280>` и перегрузке для вектора. Такой API
сохраняет C++17 без добавления внешней реализации `span`.

## Ошибки

Пустой путь, NUL в пути, отсутствие обычного файла, частота не 16000 Гц,
неположительное число потоков и несовместимый интерфейс модели дают
`std::invalid_argument`. Ошибки ONNX Runtime преобразуются в `std::runtime_error`
с контекстом загрузки/инференса. NaN/Infinity в промежуточных признаках либо
неконечная вероятность/вероятность вне `[0, 1]` также дают `std::runtime_error`.
Результат не ограничивается искусственно до допустимого диапазона.
После ошибки инференса история может быть частично обновлена; для нового
потока следует создать новый детектор. Модуль не логирует ошибку перед повторным
выбрасыванием; обработка и логирование ошибки принадлежат вызывающей стороне.

## Комплект «Нафаня»

Выбрана [публичная модель сообщества](https://github.com/fwartner/home-assistant-wakewords-collection/tree/main/ru/nafanya),
добавленная в PR #72; загрузчик закрепляет commit
`3342878221ae06b09f46cc38a74182ac00b926df`. Общие ONNX-модели берутся из релиза
OpenWakeWord v0.5.1. `oww/DownloadModels.cmake` загружает файлы отдельной командой
в `oww/models`; обычная сборка и работа детектора не используют сеть.
Неполные загрузки имеют суффикс `.part` и не устанавливаются как модели.
Совместимость фактического комплекта проверяется `oww_model_tests`, качество
распознавания — отдельно на размеченных аудиозаписях.
