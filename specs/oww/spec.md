# Определение ключевого слова

ID: OpenWakeWord

## Цель
Позволить пользователю по кадру аудио определять вероятность ключевого слова в этом кадре.

## Требования
- OWW-001: Система должна хранить путь к модели ключевого слова и проверять существование обычного файла модели при создании детектора. Аналогично проверяются файлы двух общих моделей признаков OpenWakeWord.
- OWW-002: Система должна иметь функцию, в которую передаётся кадр аудио на 80 мс: 1280 отсчётов моно signed PCM16 с частотой 16000 Гц. Функция возвращает вероятность ключевого слова типа `float` от 0 до 1.
- OWW-003: Используется CPU-пайплайн OpenWakeWord в формате ONNX: спектрограмма → акустические признаки → бинарный классификатор одного слова, в том числе пользовательской модели «Нафаня». Пути к трём файлам настраиваются; общие модели по умолчанию ищутся рядом с классификатором под именами `melspectrogram.onnx` и `embedding_model.onnx`.
- OWW-004: Модели загружаются и прогреваются при создании; рабочие буферы и тензоры выделяются заранее и переиспользуются между кадрами. По умолчанию используется один поток инференса внутри каждой последовательно исполняемой модели. Модуль не создаёт фоновых потоков и не выполняет файловый ввод-вывод на кадр.
- OWW-005: Отсутствующие/недоступные файлы, некорректные параметры и несовместимые интерфейсы моделей отклоняются. Ошибки загрузки и выполнения модели сообщаются исключением; недопустимый численный результат не заменяется фиктивной вероятностью.


## Границы
- Функция из требования OWW-002 возвращает конечное число с плавающей точкой от 0 до 1.
- Проверка длины кадра в функции обработки не выполняется. Вызывающий код обеспечивает доступность 1280 отсчётов. Неполный/нулевой буфер нарушает предусловие; вектор передаёт первые 1280 отсчётов без копирования и проверки размера.
- Один экземпляр обрабатывает один поток с сохранением контекста между кадрами; вызовы выполняются последовательно. Контекст до первого кадра заполняется тишиной при прогреве, поэтому начальное состояние воспроизводимо.
- Поддерживается бинарный ONNX-классификатор с входом float32 `[1, N, 96]`, где `N` — фиксированное число кадров от 1 до 120, и одним выходным значением float32. Динамический размер batch допускается и при выполнении равен 1. Многоклассовые и TFLite-модели, ресемплинг, захват микрофона и обучение модели не входят в модуль.
- Публичный интерфейс совместим с C++17: указатель на кадр с фиксированным контрактом, а также перегрузки для `std::array` и `std::vector`. `std::span` из первоначального плана не используется, поскольку требует C++20.
- Внутренняя память ONNX Runtime управляется самим runtime. Предварительное выделение буферов модуля не является гарантией отсутствия любых аллокаций внутри сторонних операторов.

## Критерии приёмки
- Система проверяет существование всех моделей на моменте создания и сохраняет исходный путь к классификатору.
- Валидный комплект ONNX-моделей позволяет создать детектор; существующий повреждённый файл не считается валидной моделью.
- Последовательные кадры проходят все три этапа с сохранением перекрытия PCM и контекста признаков; результат соответствует вычислениям моделей и находится в `[0, 1]`.
- Ошибочные типы/размерности моделей и NaN/Infinity/выход за диапазон вероятности приводят к исключению.
- Автоматические тесты работают без сети на небольших вычислительных ONNX-графах; отдельный smoke-тест может проверять обученную модель. Проверка качества распознавания «Нафани» на реальных записях и измерения на Raspberry Pi выполняются отдельно от проверки API.
