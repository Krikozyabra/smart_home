# Модуль командного интерфейса (CLI)

ID: Cli

Статус: спецификация адаптера командной строки и реестра диспетчеризации.
Технические решения: [design.md](design.md). План: [plan.md](plan.md).

## Цель

Предоставить типобезопасный модульный командный интерфейс (CLI) на основе паттерна
«Команда» (Command Pattern) и реестра быстрого поиска команд, отделяющий синтаксический
разбор, валидацию аргументов и форматирование ответов от бизнес-логики и основного
цикла приложения для детерминированного тестирования в памяти и интерактивной отладки.

## Требования

- CLI-001: Модуль предоставляет абстрактный интерфейс команды `ICliCommand`:
  - `name() const noexcept -> std::string_view` — строковый идентификатор (глагол) команды;
  - `validate(const std::vector<std::string_view> &args, std::string &error) const -> bool` —
    проверка наличия, количества и корректности переданных аргументов;
  - `execute(const std::vector<std::string_view> &args, ICliOutputSink &sink) -> void` —
    вызов прикреплённого обработчика с передачей вывода в `sink`.
- CLI-002: Модуль предоставляет универсальный класс `ActionCommand`, реализующий `ICliCommand`
  для команд с фиксированным числом параметров (`scan`, `save`, `help`, `list`, `exit`).
  Имя команды, требуемое число аргументов и функциональный обработчик
  задаются через конструктор.
- CLI-003: Модуль предоставляет специализированные классы команд:
  - `ShowCommand` (имя `"show"`) — ожидает ровно 1 целочисленный неотрицательный аргумент `DeviceId`;
  - `DeviceCommand` (имя `"device"`) — адресная операция над устройством:
    `device <id> <operation> [arguments]`;
  - `GroupCommand` (имя `"group"`) — групповая операция по комнатам и категориям:
    `group <room> <type> <operation> [arguments]`.
- CLI-004: Модуль предоставляет процессор команд `CliProcessor`:
  - `registerCommand(std::unique_ptr<ICliCommand> command)` регистрирует команду и индексирует
    её в `std::unordered_map<std::string, std::unique_ptr<ICliCommand>>` по ключу `name()`;
  - `processLine(std::string_view line, ICliOutputSink &sink) -> CliStatus` выполняет
    однократное разбиение строки на токены, поиск команды в хеш-таблице за O(1),
    вызов `validate`, а затем `execute`.
- CLI-005: Унифицированный синтаксис с глаголом впереди: все команды без исключения
  начинаются со своего зарегистрированного имени. Строки, начинающиеся не с известной команды,
  отклоняются процессором со статусом `CommandNotFound` и сообщением `Error: Unknown command: <name>`.
- CLI-006: Изоляция операций runtime: команды `scan` и `save` не выполняют низкоуровневую работу
  внутри модуля `cli`. Они валидируют отсутствие лишних аргументов и вызывают лямбда-обработчики,
  переданные в конструктор вызывающим кодом (`src/main.cpp` или тестовым окружением).
- CLI-007: Валидация аргументов операций строго проверяет типы и диапазоны значений:
  - `on_off.set`: ровно 1 аргумент, значение `true` или `false`;
  - `brightness.set`: ровно 1 целочисленный аргумент в диапазоне `[0, 100]`;
  - `color.set`: ровно 3 целочисленных аргумента в диапазоне `[0, 255]`;
  - операции чтения `*.get`: аргументы отсутствуют, операция проверяется по известным дескрипторам.
  При нарушении правил функция возвращает `false`, а поле `error` заполняется диагностикой.
- CLI-008: Категории `light` и `temperature_sensor` являются соглашением CLI-адаптера
  и определяются динамически по дескриптору способностей устройства (`on_off` / `brightness`
  для `light`, `temperature` для `temperature_sensor`), не требуя хранения типа в схеме онтологии.
- CLI-009: Модуль абстрагирует каналы вывода через интерфейс `ICliOutputSink`
  (`writeLine`, `writeError`). Предоставляются реализации `StreamCliSink` для терминальных
  потоков `std::ostream` и `StringCliSink` для тестов в оперативной памяти.
- CLI-010: Ошибки валидации (неизвестная команда, неверное число аргументов, значения вне
  диапазона) не выбрасывают исключений, а передаются в `sink.writeError(...)` и возвращают
  статус `CliStatus::ValidationError` или `CliStatus::CommandNotFound`.

## Синтаксис команд и форматирование ответов

Таблица поддерживаемых команд:
| Команда | Аргументы | Описание |
|---|---|---|
| `help` | — | Вывод списка команд и поддерживаемых операций |
| `list` | — | Вывод списка всех устройств с их комнатой и типом |
| `show` | `<id>` | Вывод детальной информации об устройстве и всех его значениях |
| `scan` | — | Запуск процесса обнаружения устройств |
| `save` | — | Запрос фиксации текущего состояния на диск |
| `exit` | — | Штатное завершение работы приложения |
| `device` | `<id> <operation> [arguments]` | Адресное выполнение операции на устройстве |
| `group` | `<room> <type> <operation> [arguments]` | Групповое выполнение операции над устройствами в комнате |

Форматы стандартных сообщений:
- `Device 1 on_off.set: applied`
- `Device 1 brightness.get: 75`
- `Device 1 color.get: 255 128 0`
- `Device 2 error: Capability not supported`
- `Error: Unknown command: bogus`
- `Error: Command 'scan' expected 0 arguments.`
- `Error: Boolean must be true or false.`
- `Error: RGB component must be 0..255.`
- `Error: Unknown operation or wrong argument count.`

## Ошибки и инварианты

- Пустая строка ввода или строка только из пробелов возвращает `CliStatus::EmptyInput` без вывода ошибок.
- Повторная регистрация команды с уже существующим именем в `CliProcessor` отклоняется с `std::invalid_argument`.
- Передача `nullptr` в `registerCommand` запрещена (`std::invalid_argument`).
- Команда `device` с неизвестным `DeviceId` передаётся в вызывающий обработчик; ошибка несуществующего устройства форматируется как `Device <id> error: <reason>`.
- Команда `group` при отсутствии подходящих устройств возвращает ошибку `No matching devices.`.
- Ошибки выполнения на одном из устройств группы не прерывают обработку остальных устройств.

## Границы

- Модуль выполняет однократное разбиение строки на токены, поиск команды по хеш-таблице,
  валидацию структуры и диапазонов аргументов и вызов прикреплённого обработчика.
- Модуль НЕ владеет дескриптором `stdin`, не выполняет неблокирующий опрос дескрипторов
  (буферизация ввода и `poll(2)` осуществляются через `runtime::ConsoleInput` и `events::Reactor`).
- Модуль НЕ выполняет файловые снимки (`SaveWorker`) и фоновое обнаружение (`discovery`).
- Модуль НЕ привязан жестко к доменным классам: любые внешние действия передаются в команды
  снаружи через конструкторы.

## Критерии приёмки

- Все команды начинаются со своего имени; поиск любой зарегистрированной команды
  в `CliProcessor` выполняется за $O(1)$.
- Неизвестное первое слово строки приводит к статусу `CommandNotFound` и сообщению об ошибке.
- Команды с неверным числом аргументов отклоняются методом `validate` с информативным текстом.
- `execute()` вызывается строго после успешного прохождения `validate`.
- Операции над устройствами (`device`) валидируют числовой ID, операцию и диапазоны аргументов.
- Групповые операции (`group`) валидируют параметры комнаты, типа и операции.
- Все классы компилируются в стандарте C++17 со строгими предупреждениями (`-Wall -Wextra -Wpedantic`).
- Модульные тесты CTest покрывают 100% команд, регистрацию, валидацию и сценарии ошибок
  в памяти через `StringCliSink` без создания процессов и файлов.
