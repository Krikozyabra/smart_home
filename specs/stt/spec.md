# Модуль распознавания речи (STT)

ID: STT

## Цель

Обеспечить локальное преобразование записанного речевого аудиофрагмента (PCM16 16000 Гц)
в текстовую строку на русском языке с использованием легковесного офлайн-инференса
движка `sherpa-onnx` и акустической модели `GigaAM-v3` на Raspberry Pi 4b.

## Требования

- STT-001: Система настраивается структурой `SttConfig`, содержащей пути к файлу
  модели GigaAM-v3 (`.onnx`) и словарю символов/токенов (`tokens.txt`), число потоков
  CPU (по умолчанию 2), частоту дискретизации (16000 Гц) и метод декодирования.
  Существование и доступность файлов проверяются функцией `validateConfig()` до открытия
  ресурсов.
- STT-002: Модуль принимает аудиоданные в формате signed PCM16 с частотой 16000 Гц,
  моно (в порядке байтов хоста). Поддерживается передача через непрерывный буфер
  отсчётов `std::vector<std::int16_t>` и через сырой указатель со счётчиком отсчётов.
  Нормализация отсчётов в диапазон float `[-1.0, 1.0]` выполняется внутри модуля.
- STT-003: Модуль выполняет акустический инференс и декодирование через движок
  `sherpa-onnx` в режиме офлайн-распознавания (non-streaming CTC):
  извлечение 64-мерных признаков Fbank (16 кГц) → акустическая модель GigaAM-v3
  Conformer-CTC → CTC greedy-декодирование по словарю токенов.
- STT-004: Результат распознавания возвращается структурой `SttResult`:
  распознанный текст на русском языке в кодировке UTF-8, длительность обработанного
  аудиофрагмента, а также список токенов/таймстемпов при их доступности.
- STT-005: Модели и сессия инференса загружаются и прогреваются при создании распознавателя.
  Рабочие буферы выделяются заранее и переиспользуются между вызовами. Модуль
  не создаёт скрытых фоновых потоков и не выполняет файловых операций в процессе
  распознавания аудио.
- STT-006: Отсутствующие или повреждённые файлы модели, недопустимое число потоков (<= 0),
  несовместимая частота дискретизации или сбои инференса вызывают `std::invalid_argument`
  или `std::runtime_error`. Невалидный аудиосигнал (NaN/Inf) отсекается до вызова
  нейросетевого инференса.

## Конфигурация и форматы

| Параметр | Значение по умолчанию | Описание |
|---|---|---|
| `model_path` | `""` | Путь к ONNX-модели GigaAM-v3 (FP32 или INT8); непустой |
| `tokens_path` | `""` | Путь к файлу словаря токенов `tokens.txt`; непустой |
| `sample_rate_hz` | 16000 | Частота дискретизации входного сигнала (фиксировано 16000) |
| `feature_dim` | 64 | Размерность признаков Fbank модели GigaAM-v3 |
| `num_threads` | 2 | Число потоков инференса на CPU (диапазон 1..4 для Raspberry Pi 4b) |
| `decoding_method` | `greedy_search` | Алгоритм CTC-декодирования (`greedy_search` или `modified_beam_search`) |

Пустые пути, несуществующие файлы, неположительное число потоков и неподдерживаемая
частота дают `std::invalid_argument` в `validateConfig()`.

## Владение и потокобезопасность

- Публичный интерфейс `ISttRecognizer` и класс `SherpaSttRecognizer` скрывают
  внутренние структуры `sherpa-onnx` и `onnxruntime` через PIMPL (`std::unique_ptr<Impl>`).
  Публичный API совместим со стандартом C++17.
- Один экземпляр распознавателя обрабатывает один аудиофрагмент за раз. Вызовы метода
  `recognize()` последовательны. Разделяемое владение между потоками без синхронизации
  не допускается.
- Для многопоточного использования создаются независимые экземпляры либо доступ
  синхронизируется вызывающим кодом.
- Деструктор освобождает все ресурсы ONNX Runtime и движка без исключений.

## Границы

- Модуль выполняет преобразование законченного аудиофрагмента в текст. Захват звука
  с микрофона, непрерывный кольцевой буфер и определение окончания речи (VAD)
  принадлежат модулю `audio` и контроллеру голосового тракта.
- Определение ключевого слова активации («Нафаня») выполняется модулем `oww`.
- Синтез речи (TTS), семантический парсинг текста (NLU) и диспетчеризация команд
  в устройства умного дома не входят в область ответственности модуля STT.
- Ресемплер отсутствует: входной сигнал обязан иметь частоту 16000 Гц.
- Вычисления производятся на CPU; аппаратное ускорение GPU/NPU не требуется.

## Критерии приёмки

- Валидация отклоняет несуществующие пути к файлам модели и токенов с `invalid_argument`.
- Корректный комплект модели GigaAM-v3 и словаря токенов успешно инициализирует
  распознаватель и проходит тестовый прогрев при создании.
- Передача эталонного аудиофайла (PCM16 16 кГц) возвращает непустой распознанный текст,
  соответствующий произнесённой русской фразе.
- Пустой входной вектор или буфер нулевой длины возвращает пустой результат `SttResult`
  без сбоев и исключений.
- Повторные последовательные вызовы `recognize()` не приводят к утечкам памяти
  и деградации времени распознавания.
- Типы и заголовочные файлы `sherpa-onnx` не выходят в публичные заголовки `include/stt/`.
- Автоматические тесты в `tests/SttTests.cpp` проверяют валидацию, форматы и инференс
  на компактной тестовой ONNX-модели без зависимости от внешней сети.
