# Консольная проверка audio и oww

Исполняемый файл `smart_home_audio_oww_demo` связывает существующие публичные
API в `src/`; поведение библиотек не меняется. Это ручная диагностическая
программа, а не готовый голосовой сценарий приложения.

- Параметры CLI: обязательный `--model`, необязательные `--device` (default),
  `--melspec`, `--embedding` и `--threshold` (0.5, конечное число в (0, 1]).
  Общие модели по умолчанию находятся рядом с классификатором.
- Формат захвата фиксирован: 16000 Гц, Mono, PCM16, кадр 80 мс.
- `start` запускает непрерывный захват и последовательную обработку снимков;
  повторный start ничего не меняет. `stop` останавливает микрофон, обрабатывает
  оставшиеся полные кадры и печатает итог; повторная остановка безопасна.
- `sample` в остановленном режиме записывает ровно 5 секунд в RAM, затем
  обрабатывает запись новым детектором. Во время live команда отклоняется
  с предложением сначала выполнить stop. Запись не сохраняется на диск.
  80000 отсчётов дают 62 полных кадра и 640 отсчётов; последний кадр дополняется
  640 нулями. Всего обрабатываются 63 кадра, включая 40 мс добавленной тишины.
- `help` показывает команды; `quit` и EOF останавливают запись и завершают
  приложение. Неизвестная команда выводит подсказку без завершения.
- Печатаются вероятность первого и затем примерно каждого секундного кадра,
  уведомления WAKE WORD при переходе вероятности через порог снизу вверх,
  итоговые число кадров, пиковая вероятность и число срабатываний. Порог —
  диагностическая настройка, не гарантия качества распознавания.
- Снимки читаются одним потребителем без повторной обработки sequence.
  Новый сеанс или пропуск кадров сбрасывает контекст пересозданием детектора;
  пропуск явно показывается. Модели готовятся до старта микрофона, а не
  загружаются на каждом кадре. Обработка и консоль выполняются в одном потоке;
  на медленной системе возможен пропуск, обнаруживаемый по sequence.
- Ошибка захвата/инференса завершает приложение с ненулевым кодом и явным
  сообщением; ресурсы освобождаются RAII. Пустой ввод не запускает захват.

Автотест использует программный PCM ALSA `null` и маленькие ONNX-графы без
сети и микрофона. Он проверяет команды, оба режима, дополнение последнего
кадра и порог; качество распознавания и задержки на Raspberry Pi проверяются
отдельно с настоящим микрофоном и обученными моделями.

## Проверки реализации (2026-11-07)

| Команда | Результат |
|---|---|
| `cmake -S . -B build` | Успех |
| `cmake --build build --target smart_home_audio_oww_demo -j 4` | Успех, C++17, без предупреждений компилятора |
| `cmake --build build --target audio_config_tests audio_capture_tests audio_buffer_tests audio_concurrency_tests oww_tests oww_model_tests -j 4` | Успех |
| `ctest --test-dir build -R '^(audio_.*\|oww_.*)$' -LE hardware --output-on-failure` | 8/8, включая два console-теста и smoke настоящей модели |
| `cmake --build build --target docs` | Успех |
| `clang-format --dry-run --Werror src/audio_oww_demo.cpp` | Успех |
| `git diff --check` | Успех |

Дополнительно приложение запущено с `--device null --model
oww/models/nafanya.onnx`, на stdin переданы `sample`, `quit`: код 0,
80000 отсчётов, 63 кадра, peak 0.0008, 0 срабатываний.
Аналогичный запуск с настоящим `--device plughw:1,0` также завершился
успешно: 80000 отсчётов, 63 кадра, peak 0.0008, 0 срабатываний.
Данные микрофона не сохранялись на диск.

Автотест проверил live-обработку без ввода, повторный start/stop, отклонение
sample во время live, новый сеанс, завершение по EOF, sample с порогом выше
и ниже результата модели, неверные параметры/устройство/модель и явные пути
моделей. Python нужен только для запуска интеграционного теста; бинарный
файл приложения зависит от C++-модулей audio/oww.

Не проверены: качество обнаружения произнесённого слова, live-режим с
настоящим микрофоном, длительный захват и нагрузка/задержки на Raspberry Pi.
Полный CTest остальных модулей в этой задаче не запускался.
