# План реализации модуля audio

Статус: план одобрен пользователем; пункты реализации не выполнены.
Основание: [спецификация](spec.md) и [технические решения](design.md).
План учитывает C++17, структуру существующих `oww` и `ontology`,
их тесты и ограничения Raspberry Pi 4b.

## 1. Соответствие требованиям

| Требование или критерий | Реализация | Проверка |
|---|---|---|
| AM-001: выбор микрофона и параметров | `AudioConfig`, проверка размеров и установка ALSA PCM | Конфигурационные тесты и отдельный тест реального устройства |
| Несуществующий микрофон вызывает ошибку | Открытие устройства в конструкторе | Ошибка открытия, освобождение частичных ресурсов |
| Можно прочитать настройки | `getConfig()` возвращает копию | Сохранение всех переданных значений |
| AM-002: непрерывная запись в отдельном потоке | `startContinuous()`, worker, `stopContinuous()` | Идентификатор потока чтения источника отличается от вызывающего |
| Только worker пишет в кольцо | Приватная публикация полных кадров | Все публикации принадлежат одному worker, OneShot не меняет кольцо |
| Чтение из любого потока | `snapshot()` и mutex кольца | Несколько читателей, согласованные независимые копии |
| AM-003: разовая запись в PCM-вектор | Синхронный `recordFor(duration)` | Точная длина, значения PCM и чередование каналов |

## 3. Тестирование

Использовать существующий подход `tests/TestUtil.h` и самостоятельные
исполняемые CTest-тесты. Точки подстановки источника доступны только тестам,
по образцу приватных test seams модуля ontology.

| Набор | Существенные проверки |
|---|---|
| `AudioConfigTests.cpp` | Значения по умолчанию; все поля конфигурации; пустое имя/NUL; нулевые и отрицательные величины; неизвестный канал; дробное число отсчётов; переполнения и границы размеров |
| `AudioCaptureTests.cpp` | Моно/стерео PCM16 с известными значениями; точное число отсчётов, включая последний короткий фрагмент; короткие чтения; EINTR/EAGAIN; ошибка открытия/формата/чтения; освобождение ресурсов; отсутствие частичного результата при сбое |
| `AudioBufferTests.cpp` | Пустое кольцо; заполнение и многократный оборот; порядок кадров; перезапись; независимость снимка; полный кадр без разрыва; метаданные сеанса и обнаружение пропусков |
| `AudioConcurrencyTests.cpp` | Захват в отдельном потоке; единственный писатель; несколько читателей; конфликты режимов; повторные start/stop; конкурентная остановка; пробуждение при отсутствии данных; join; сохранённая ошибка; очистка и новый сеанс после штатного restart |

Синхронизировать тесты через управляемые события и барьеры C++17
на mutex/condition_variable. Проверять содержимое данных и наблюдаемое
поведение, а не только счётчики вызовов. Для CTest задать тайм-ауты,
чтобы зависание остановки считалось ошибкой.

Отдельный opt-in тест ALSA принимает явно заданное устройство.
Проверить успешный захват, ошибочное имя PCM и отказ неподдерживаемого
формата, когда это воспроизводимо на выбранном оборудовании.
Без микрофона этот этап считается невыполненным.

Для связки с oww проверить соответствие 16000 Гц, Mono, 80 мс и 1280
отсчётам, последовательность кадров и реакцию потребителя на разрыв.
Это не проверка качества распознавания ключевого слова.

## 4. Сборка и проверка реализации

После реализации использовать отдельный build-каталог. Пути SDK
Ladybug/ONNX Runtime передать согласно фактической локальной конфигурации;
не считать наличие этих зависимостей гарантированным.

```sh
cmake -S . -B /tmp/smart-home-audio/build -DCMAKE_BUILD_TYPE=Debug
cmake --build /tmp/smart-home-audio/build -j 4
ctest --test-dir /tmp/smart-home-audio/build --output-on-failure
cmake --build /tmp/smart-home-audio/build --target docs
git diff --check
```

При необходимости добавить параметры SDK в команду конфигурации.
Выполнить проверку публичного потребителя с C++17, принятые проверки
форматирования изменённого C++-кода и ThreadSanitizer для тестов
конкурентного доступа, если среда его поддерживает. Невозможность запуска
санитайзера отмечать отдельно от результата тестов.

На Raspberry Pi с реальным микрофоном проверить оба режима, несколько
читателей и многократные запуски/остановки. Измерить CPU, память и задержку
остановки на длительном захвате; подтвердить отсутствие накопления памяти
и записи PCM на SD-карту. Сопоставить скорость потребителя с ёмкостью
кольца и проверить видимость пропусков при намеренном замедлении.
